# CADLint

矢量 PDF 图纸检查应用。已实现产品类别、项目、图纸、PDF 内容流与文字位置解析、DeepSeek 基准草案学习及文字对比、按类别发布的输入质量规则，以及项目内的可执行流程，沿用 AutoReg 的 Next.js 15、React 19、TypeScript 技术栈。原有 NX PDF 检查脚本保留在 `nx-pdf-drawing-inspection/`。

## 本地运行

需要 Node.js 20+、Python 3.9+ 和 npm。

```bash
./scripts/local-setup.sh
./scripts/local-start.sh
```

打开 `http://127.0.0.1:3100`。首次进入没有预置项目；先通过页眉创建产品类别，再创建项目。可从 `.local-verification/samples/` 上传 `vector-line.pdf` 和 `blank-page.pdf`，比较分析结果。按 `Ctrl+C` 停止服务。页面支持中文与英文。

`local-setup.sh` 会安装 Node/Python 依赖、运行解析测试和正式构建、生成样例 PDF，并用临时数据目录完成接口自检；不会向正式验证数据预置项目。再次自检可运行 `node scripts/smoke-local.mjs`。需要更换端口时设置 `CADLINT_PORT`，例如 `CADLINT_PORT=3200 ./scripts/local-start.sh`。

服务端 AI 默认使用 DeepSeek：设置 `DEEPSEEK_API_KEY`，可用 `DEEPSEEK_MODEL` 和 `DEEPSEEK_VISION_MODEL` 指定模型。也可设 `CADLINT_AI_PROVIDER=bedrock`、`AWS_REGION` 和支持图片输入的 `BEDROCK_MODEL_ID`，由 AWS SDK 使用部署环境的 IAM 角色或标准 AWS 凭证调用 Bedrock Converse。浏览器不会收到密钥。`/api/ai/status` 的“已配置”仅表示必要环境变量齐全，不代表账户已开通模型或真实请求已验收。未配置时仍可运行确定性规则和人工复核。两种接口的本地自检都使用模拟服务，不调用真实模型；部署后需以真实账户验证权限、费用和准确率。配置示例见 `frontend/.env.example`。

可创建产品类别和项目，上传 PDF、查看项目图纸列表与预览。选择图纸后点击“分析矢量内容”，应用会复用仓库中的 Python POC 脚本，记录每页路径绘制、文字操作、XObject 调用数量及文件校验值；另将可直接读取的线段、贝塞尔曲线和矩形按显示坐标保存为矢量对象（每页最多 20,000 个对象、每对象最多 200 个绘图命令，并明确标记截断）。Form XObject 内部几何暂未展开。在“产品类别与规则”中可编辑草稿、发布版本；同类别项目复用最新发布版本。在“检查任务”中可以对已分析图纸单独运行输入质量检查。

分析成功后，服务端会把 PDF 可提取文字交给 DeepSeek 识别显式工程要求，核对模型引用的页码和原文，再自动加入对应产品类别的“工程要求规则”候选清单。用户可查看原图和引用、修正文字、确认或忽略；规则保留来源与修订历史，重新提取不会重复创建相同原文。确认表示人工认可要求内容，**不代表已有自动检查能力**：当前工程要求不进入可执行输入质量规则发布包。新建检查任务时会固定该类别已确认要求的文字、修订号和来源，用户可逐条记录符合、不符合、不适用或待跟进的人工判断及依据；报告保存当时的判断快照。后续修改类别规则或复核不会改变旧检查和旧报告。每页最多提取 12,000 字符、每次最多提交 60,000 字符，单次最多生成 20 条候选；若文字截断，界面会提示覆盖不完整。扫描件、转曲文字及未可靠提取的注记需人工核对。未来可增加 ChatGPT 辅助修改规则，当前服务端仍仅调用 DeepSeek。

“基准学习”页可对已分析的矢量 PDF 发起 AI 要素提取，形成带来源页码、文字和可定位文字起点（若有）的版本化草案。候选按图纸标识、视图标签、尺寸文字、GD&T 文字和技术注记展示。PDF 文字层引用必须能在原页文字中核对，否则整次学习失败并保留调用记录；有文字坐标时，系统会列出 24 PDF 点范围内最近的三个矢量路径及距离，作为人工查看的空间候选，不视作已验证的标注连接。对文字转曲或只有图片的页面，服务端最多处理前三页：以 200 DPI 渲染后按实际像素尺寸分成最多 3×3 个重叠区域，逐区提交模型图片输入。视觉候选必须返回有效区域 ID，用户可打开对应裁图对照原图确认或修正；模型还可提出视图、形状特征和标注关系的低置信度观察候选。所有视觉候选必须逐项确认或排除才能批准基准，且形状和关联尚未由矢量几何验证。图片原始数据总量限制为 30 MiB，超限会报错；Bedrock 单张图片限制为 3.75 MB，并按页面分批调用以满足每次最多 20 张的限制。特别大的区域仍可能被模型缩小，并在基准限制中提示。用户可补充遗漏的 PDF 文字层原文；同页重复文字会按可定位的出现位置分别形成候选，逐项确认或排除后才能批准基准；批准版本不可原地修改。选择已批准基准和目标图纸后，系统优先按同页最近文字坐标配对，生成不可变的文字差异记录（相同、新增、缺少、页码变化、页内位置变化）；文字缺少可用坐标时标为位置待判定，不强制认定为同一位置。记录包含两份 PDF 的哈希、解析执行 ID 和模型版本。**这仍是受限的文字与视觉候选基准**：文字位置只是近似起点，视觉识别未通过 PDF 文字层验证；图形特征识别、标注与几何的连接、尺寸公差计算尚未实现。所有差异均需人工复核，不能作为工程合规 PASS/FAIL。视觉回退需要系统提供 Poppler 的 `pdftoppm`，可通过 `CADLINT_PDFTOPPM` 指定可执行文件。实际 DeepSeek 或 Bedrock 账户接入均留待部署后联调和准确率验收；目前的端到端测试使用模拟接口。

项目内“流程”页可配置已有分析结果是否复用、何时进行人工复核，保存草稿并发布流程版本。运行流程会依次执行 PDF 分析、类别输入质量规则和可选的人工复核；运行记录固定流程、规则及 PDF 版本，解析失败也有节点状态记录。流程级复核可记录“确认完成”或“需处理”。“问题复核”页进一步针对每条待确认结果记录判断、备注和追加式历史，展示原始 PDF 页及同页路径范围定位图；坐标已考虑页面裁剪和 0/90/180/270 度旋转，但定位图只显示内容流中可直接识别的路径（最多前 200 个区域），不解析 Form XObject 内部路径、文字边界或 CAD 对象，也不是完整 PDF 渲染。“检查任务”页记录已确认工程要求的人工判断。“报告”页可针对一次检查生成不可变快照，查看当时的输入质量结果和工程要求人工判断，打开可打印 HTML 或下载 HTML。重新生成报告会产生新快照，旧报告不随复核变化。规则原始结果保持不变。

当前流程只有这三个已接入节点，并非完整 CAD 语义检查流程；未达到输入质量阈值的结果标记“待人工确认”，不能视为 CAD 几何、尺寸或标注不合格。DeepSeek 与 Bedrock 可切换用于输入质量建议、工程要求和基准候选；真实账户联调、工程要求的检查算子、其他 AI 场景和账号权限仍待后续批次完成。

本地验证数据保存在 `.local-verification/data/`，每次分析输出单独保存在 `analysis/<图纸 ID>/<执行 ID>/`；也可通过 `CADLINT_DATA_DIR` 指定其他目录。Python 可执行文件默认使用 `backend/.venv/bin/python`，也可通过 `CADLINT_PYTHON` 覆盖。流程、规则、复核和报告目前保存在本地 JSON 数据库，适用于单实例验证；生产部署需替换为数据库、文件存储和可靠任务队列，并加入身份权限、操作者身份记录与发布审批。
